# Техническое задание: исследование, переписывание и публикация гайдов Relocate to Asia

**Проект:** `www.marharuta.online`  
**Язык первого этапа:** русский  
**Дата ТЗ:** 8 октября 2026 года  
**Цель:** превратить каждый гайд в самостоятельную полезную статью, которая отвечает на поисковый вопрос лучше конкурентов, содержит проверенные цифры и помогает принять конкретное решение.

## 1. Объём работ

Первый этап включает следующие страницы:

1. `/ru/guides/can-you-extend-japan-digital-nomad-visa/`
2. `/ru/guides/japan-digital-nomad-visa-income-requirement/`
3. `/ru/guides/thailand-dtv-vs-ltr-visa/`
4. `/ru/guides/malaysia-de-rantau-vs-thailand-dtv/`
5. `/ru/guides/taiwan-gold-card-income-requirement/`
6. `/ru/guides/best-asian-countries-with-easy-long-stay-visas/`
7. `/ru/guides/where-to-live-in-asia-on-1500-a-month/`
8. `/ru/guides/best-asian-countries-for-remote-workers-with-family/`
9. `/ru/guides/philippines-srrv-vs-thailand-retirement-visa/`

Страница `/ru/guides/` является каталогом, а не статьёй. Для неё проводится отдельная проверка навигации, описаний и внутренних ссылок, но не применяется требование пяти конкурентов и длинного текста.

После завершения русского этапа английские версии проходят отдельное исследование в англоязычной выдаче. Перевод русского текста без повторной проверки английского интента не допускается.

## 2. Результат для каждого гайда

Для каждого URL должны быть подготовлены:

1. снимок живой поисковой выдачи;
2. пять релевантных конкурентов;
3. таблица ключевых фраз конкурентов;
4. данные Google Search Console по существующему URL;
5. кластер ключевых фраз Serpstat;
6. аудит текущей страницы;
7. новая структура статьи;
8. полностью переработанный текст;
9. реестр проверенных фактов и первоисточников;
10. SEO Title, H1, meta description и анонс;
11. список внутренних ссылок;
12. редакционный отчёт;
13. результаты технической и визуальной проверки;
14. опубликованная страница с подтверждением доступности.

## 3. Этап 1. Выбор пяти конкурентов из живого поиска

### 3.1. Поисковая база

- Исследование проводится в день работы, а не по сохранённому старому списку.
- Для русскоязычных формулировок проверяется русская выдача.
- Для официальных английских названий виз дополнительно проверяется Google US.
- Указываются дата, региональная база, язык и точная поисковая фраза.
- Страница не называется лидером выдачи без фактической проверки позиции.

### 3.2. Правила выбора

В итоговые пять конкурентов включаются страницы, которые:

- отвечают на тот же поисковый вопрос;
- являются статьями, гайдами или сравнительными материалами;
- содержат содержательный текст, а не только форму продажи услуги;
- доступны для чтения без обхода paywall;
- опубликованы или обновлены достаточно недавно для текущей темы.

Не включать в основные пять:

- страницы с другим интентом;
- главные страницы компаний;
- форумы и Reddit как замену статье;
- агрегаторы без собственного содержания;
- PDF государственных органов — они относятся к первоисточникам, а не конкурентам;
- страницы Relocate to Asia.

Reddit, форумы и видео можно использовать только как дополнительный источник вопросов пользователей. Они не заменяют конкурентов и официальные источники.

### 3.3. Что фиксировать по конкуренту

| Поле | Требование |
|---|---|
| URL | Прямая ссылка на материал |
| Домен | Название сайта |
| Поисковый запрос | По какой фразе найден материал |
| Позиция | Фактическая позиция в проверенной выдаче, если доступна |
| Title и H1 | Без исправления формулировок |
| Дата | Дата публикации или обновления, если указана |
| Объём | Ориентировочное количество слов |
| Структура | Все содержательные H2/H3 |
| Таблицы и инструменты | Какие элементы помогают читателю принять решение |
| Источники | Есть ли ссылки на государственные сайты |
| Сильные стороны | Что конкурент объясняет хорошо |
| Слабые стороны | Какие вопросы остаются без ответа |
| Коммерческий уклон | Продаёт ли конкурент консультацию или визу |

## 4. Этап 2. Сбор ключевых фраз

### 4.1. Источники семантики

Использовать одновременно:

- ключевые фразы URL конкурентов из Serpstat;
- Serpstat Keywords Info для основного кластера;
- Google Search Console для текущей страницы;
- Title, H1, H2 и формулировки вопросов у конкурентов;
- блоки People Also Ask и связанные запросы живой выдачи;
- официальные названия виз и программ.

API-ключи, токены и URL с токенами нельзя сохранять в коде, статье или отчёте.

### 4.2. Обязательные данные GSC

Для каждого URL выгрузить минимум последние 90 дней:

- запрос;
- клики;
- показы;
- CTR;
- среднюю позицию.

Запросы распределить по группам:

- уже близки к первой странице;
- имеют показы, но низкий CTR;
- соответствуют текущему интенту;
- требуют отдельной статьи;
- нерелевантны текущему URL.

Запрос с другим интентом нельзя вставлять в текст только ради показов.

### 4.3. Обязательные данные Serpstat

Для каждой ключевой фразы записывать:

- фразу;
- язык;
- региональную базу;
- частотность `region_queries_count`;
- широкую частотность, если доступна;
- сложность;
- CPC, если доступен;
- источник фразы;
- целевой раздел статьи.

Если Serpstat не вернул строку, значение указывается как «недоступно». Оно не заменяется нулём.

### 4.4. Кластеризация

Для одного гайда формируется один основной кластер:

- основной запрос;
- 3–8 близких дополнительных запросов;
- 3–8 вопросительных long-tail фраз;
- официальные варианты названия программы;
- естественные русские варианты терминов.

Ключевые фразы используются естественно. Запрещены искусственная плотность, повтор одного ключа в каждом заголовке и грамматически неправильные точные вхождения.

## 5. Этап 3. Создание структуры статьи

### 5.1. Основа структуры

Структура создаётся после сравнения пяти конкурентов и должна:

- закрывать общий набор вопросов конкурентов;
- устранять найденные пробелы;
- не копировать порядок и формулировки одного сайта;
- соответствовать конкретному интенту страницы;
- отделять официальное правило от редакционного вывода;
- вести читателя к следующему действию.

### 5.2. Требования к началу статьи

В первых 80–120 словах должны быть:

- прямой ответ на основной вопрос;
- главное ограничение;
- кому материал подходит;
- дата проверки правил.

Не начинать с общего описания страны или фразы «в этой статье мы расскажем».

### 5.3. Рекомендуемые блоки визового гайда

Использовать только релевантные блоки:

1. короткий ответ;
2. ключевые цифры;
3. кому подходит маршрут;
4. кому не подходит;
5. требования к заявителю;
6. подтверждение дохода;
7. документы;
8. место и порядок подачи;
9. срок действия и срок одного пребывания;
10. продление и повторный въезд;
11. право на удалённую и местную работу;
12. супруг, дети и возрастные ограничения;
13. страховка;
14. государственные и сопутствующие расходы;
15. налоги с обязательной оговоркой о персональной проверке;
16. действия после въезда;
17. ошибки и причины отказа без выдуманных процентов;
18. альтернативные маршруты;
19. пошаговый чек-лист;
20. FAQ только с вопросами, ещё не раскрытыми выше.

### 5.4. Рекомендуемые блоки сравнительного гайда

1. короткий вывод по 2–4 сценариям;
2. единая сравнительная таблица;
3. одинаковые критерии для обеих программ;
4. документы и финансовые доказательства;
5. срок, продление и обслуживание статуса;
6. семья;
7. работа и налоги;
8. первый год расходов;
9. кому подходит каждый вариант;
10. дерево решения;
11. следующий шаг.

### 5.5. Рекомендуемые блоки пенсионного гайда

1. возраст и финансовые условия;
2. депозит отдельно от расходов;
3. пенсия и другие источники дохода;
4. страховка по возрасту и исключениям;
5. больницы и различия между городами;
6. супруг и наследование;
7. банки, валюта и доступ к капиталу;
8. годовой бюджет вместо минимального месяца;
9. пробный период;
10. календарь обязательных действий.

## 6. Этап 4. Написание статьи

### 6.1. Качество текста

- Текст должен быть самостоятельным, а не пересказом конкурентов.
- Каждый раздел добавляет новую информацию.
- Абзацы преимущественно по 2–4 предложения.
- Таблицы используются для сравнения, чек-листы — для действий.
- Не растягивать материал ради формального количества слов.
- Ориентировочный объём узкого гайда: 1 400–2 200 слов.
- Ориентировочный объём хаба или большого сравнения: 2 000–3 500 слов.
- Фактическая полнота важнее объёма.

### 6.2. Факты

Любые утверждения о следующих темах проверяются по первоисточникам:

- срок визы и пребывания;
- продление;
- доход и депозит;
- сборы;
- страховка;
- разрешённая деятельность;
- работа;
- семья;
- налоги;
- требования после въезда.

Приоритет источников:

1. государственный орган или официальный портал программы;
2. посольство или консульство;
3. официальный FAQ или PDF;
4. международная организация для статистики;
5. конкурент — только для поиска вопроса, но не для подтверждения правила.

Если официальные источники расходятся, в статье объясняется область действия каждого. Нельзя выбирать удобную цифру без объяснения.

### 6.3. Авторский опыт

Нельзя приписывать Маргарите Яровенко проживание в стране, получение визы или личные расходы без предоставленных заметок. Условные примеры помечаются как условные.

### 6.4. Уникальная дополнительная польза

Каждый гайд должен иметь минимум один элемент, которого нет у большинства пяти конкурентов:

- календарь статуса;
- таблица доказательств дохода;
- расчёт первого года;
- разделение депозита и расходуемых денег;
- семейный сценарий;
- дерево решения;
- сценарий отказа или выхода;
- список вопросов консульству;
- сравнение официального правила и практического последствия.

## 7. SEO и внутренняя перелинковка

Для каждой страницы подготовить:

- уникальный H1;
- SEO Title примерно 50–65 символов;
- meta description примерно 140–165 символов;
- анонс в 1–2 предложениях;
- основной ключ в H1, Title и начале статьи, если это естественно;
- дополнительные ключи в релевантных разделах;
- 3–8 внутренних ссылок.

Внутренние ссылки должны вести только на существующие страницы и помогать следующему действию:

- страновой гайд;
- визовая статья;
- сравнение;
- калькулятор;
- планировщик бюджета;
- другой релевантный гайд.

Существующий URL сохраняется. Изменение slug требует отдельного согласования и карты редиректов.

## 8. Редакционный отчёт

Для каждого существенно обновлённого материала создать или обновить:

`docs/content-reviews/<slug>-ru.md`

Отчёт должен содержать:

1. аудиторию и интент;
2. дату и регион поиска;
3. пять конкурентов;
4. сравнительный анализ структуры;
5. таблицу ключевых фраз;
6. данные GSC;
7. распределение ключей по разделам;
8. реестр фактов и источников;
9. список внутренних ссылок;
10. выполненные проверки;
11. нерешённые вопросы;
12. итоговый статус.

Статусы: `Пройдено`, `Не пройдено`, `Не проверено`, `Не применимо`.

Материал нельзя обозначать как готовый, если не проведены Serpstat, конкурентная проверка, проверка первоисточников или визуальная проверка.

## 9. Этап 5. Публикация

### 9.1. Предпубликационная проверка

Для каждого гайда проверить:

- HTTP 200;
- один H1;
- корректные Title и description;
- canonical;
- hreflang;
- видимый блок официальных источников;
- отсутствие битых внутренних ссылок;
- отсутствие горизонтального переполнения страницы;
- читаемость таблиц;
- мобильную навигацию;
- отсутствие переносов внутри коротких слов;
- корректность валют, сроков и единиц измерения;
- отсутствие дублирования FAQ и основного текста.

### 9.2. Обязательные проверки

После стабилизации пакета запустить:

```text
python scripts/seo_audit.py
python scripts/content_quality_audit.py
python scripts/technical_audit.py
python scripts/test_editorial.py
python scripts/ru_localization_audit.py
python scripts/test_technical_regressions.py
python scripts/test_design_system.py
```

Визуально проверить минимум на ширинах:

- 1280 px;
- 820 px;
- 390 px.

### 9.3. Порядок публикации

1. Сохранить редакционный отчёт.
2. Обновить страницу в локальном проекте.
3. Проверить локальный URL.
4. Провести редакционную проверку цифр и формулировок.
5. Зафиксировать изменения в Git отдельным осмысленным commit.
6. Push выполнять только по прямому разрешению пользователя.
7. Дождаться успешного деплоя.
8. Проверить production URL, canonical, источники и основные блоки.
9. При необходимости отправить URL на переобход через Google Search Console.
10. Через 14 и 28 дней сравнить показы, клики, CTR и запросы.

## 11. Критерии приёмки одного гайда

Гайд считается готовым к публикации, если:

- выбраны и описаны пять релевантных конкурентов из живой выдачи;
- получены реальные данные Serpstat или честно зафиксирована их недоступность;
- проверены запросы GSC текущего URL;
- структура основана на интенте и пробелах конкурентов;
- текст написан самостоятельно;
- все критические цифры подтверждены первоисточниками;
- ключи включены естественно;
- есть понятный ответ, ограничения и следующий шаг;
- SEO-поля уникальны;
- внутренние ссылки существуют;
- создан редакционный отчёт;
- профильные тесты пройдены;
- страница проверена на 1280, 820 и 390 px;
- production URL отвечает 200 после публикации.

## 12. Итоговый отчёт по пакету

После каждого пакета предоставить:

- список обновлённых URL;
- пять конкурентов для каждого URL;
- основные ключевые фразы и метрики;
- краткое описание новой пользы;
- изменённые Title, H1 и description;
- список подтверждённых фактов;
- результаты тестов;
- ссылки на редакционные отчёты;
- commit hash;
- production URL и результат проверки;
- список оставшихся рисков и следующую очередь.
